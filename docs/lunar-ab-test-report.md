# 음력 변환 A/B 테스트 리포트 — KASI vs lunar-typescript

> 목적: 사주 서비스의 음력 변환을 **KASI 음양력정보 API(한국천문연구원)** 와
> **lunar-typescript(6tail, npm)** 중 무엇으로 할지 결정하기 위한 비교 테스트.
> 작성 2026-08-14. 브랜치 `test/lunar-api`.

## 1. 요약 (TL;DR)

- 두 방식은 **대부분 날짜에서 음력이 일치**하나, **1990–2030 음력 507개 달 중 21개(약 4.1%)에서 하루 어긋남.**
- 원인: **한국(KST, UTC+9) vs 중국(UTC+8) 삭(朔) 계산 기준 차이.** 삭이 자정 근처에 뜨는 달은 시작일이 하루 달라지고, 그 달 전체가 하루 밀린다.
- 어긋난 달에는 **설날(음력 1-1)이 다른 해(1997·2027·2028)** 와 **윤달 위치가 다른 해(2012·2017)** 포함 → 사주에서 연주·월주·일주까지 흔들림.
- **KASI = 한국 공식.** 한국 사주 서비스에는 KASI가 정답. lunar-typescript 단독 사용은 부적합.
- 단 KASI는 **rate-limit(호출 제한)** 이 있어 대량 호출 시 실패 → **캐싱 + 낮은 동시성** 필요.

## 2. 테스트 방식

| 항목 | 내용 |
|---|---|
| A안 | KASI `getLunCalInfo` (Express proxy `/api/lunar` 경유) |
| B안 | `lunar-typescript` `Solar.fromYmd().getLunar()` (클라이언트 로컬) |
| 정규화 | 음력 (년,월,일,윤달) 비교. lib은 leading-zero 없음·윤달은 음수월 → 맞춰서 대조 |
| 대량 대조 | **음력 월경계 샘플링** — 불일치는 월 시작(삭)이 어긋나 한 달 통째 번지므로, 각 음력 달 시작일만 KASI 조회(1990–2030, 507건). 매일 조회(~15,000건, 쿼터 초과) 회피 |

## 3. 정확성(값) 결과

- 무작위·경계 케이스(설날·윤달·먼 과거) 다수에서 **양쪽 일치** 확인.
- 1990–2030 전 구간 월경계 대조: **507개 중 21개 달 불일치.**

### 어긋난 달 21개
```
1990-10  1995-7  1995-11  1997-1(설날)  1999-12  2001-4  2005-11
2012(윤달권 4건)  2013-5  2017(윤달권 2건)  2019-11  2020-2
2023-4  2026-9  2027-1(설날)  2028-1(설날)  2029-6
```

### 주목 케이스
- **설날 불일치 (1997·2027·2028):** lib은 음력 1-1이라는데 KASI는 아직 전년 12-30. 예) 2027-2-6 → KASI 음력 2026-12-30 / lib 음력 2027-1-1.
- **윤달 배치 불일치 (2012·2017):** 단순 하루 밀림을 넘어 윤달이 몇 월에 붙는지가 갈림. 예) 2012-4-21 → KASI 윤3월 / lib 평4월.
- **일반 케이스:** 예) 2020-2-23 → KASI 음력 1-30 / lib 음력 2-1 (정월 크기 30일 vs 29일 차이). 이후 그 음력 달 내내 하루 밀림.

## 4. 신뢰성(안정성) 결과

| | KASI | lunar-typescript |
|---|---|---|
| 대량 호출 | **rate-limit 걸림.** 동시성 8 → 대부분 실패, 동시성 3 → 12% 실패, **동시성 1 → 0% 실패** | 로컬이라 **항상 성공** |
| 실패 지점 | 서버·API·키·네트워크 | 없음 |
| 응답 속도 | 네트워크 ~200ms (캐시 시 ~2–20ms) | <1ms |

## 5. 별개 이슈 — 진태양시(시주)

날짜 레이어와 무관하게, **시주(時柱)는 어느 방식을 써도 경도 보정이 따로 필요.**
KST는 동경 135°(일본) 기준이라 서울(126.98°)보다 ~32분 빠름. 서울 기준 **−32분 보정** 필요(`my-app/src/lib/solarTime.ts`). 개인 출생지별 경도차·균시차는 단순화 위해 생략.

## 6. 결론 및 권고

1. **음력 날짜는 KASI 사용** — 한국 공식. lib은 중국 기준이라 21개 달(설날·윤달 포함)에서 어긋나 사주 결과 오류.
2. **KASI는 캐싱 필수** — 날짜별 음력은 불변이므로 캐시하면 재호출 0. rate-limit·속도 동시 해결.
3. **대량 처리 시 동시성 1~2** — 버스트로 때리면 스로틀. (구현: server 메모리 캐시 + 재시도 backoff 반영됨)
4. **사주 팔자 계산은 lib 활용 가능** — 단 입력 음력은 KASI로 확정한 값을 먹이고, 시각은 진태양시 보정 후 사용.
